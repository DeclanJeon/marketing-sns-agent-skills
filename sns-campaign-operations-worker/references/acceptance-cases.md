# 실제 작업의 수용 기준

1. 개발자가 CSV 정리 도구 설명과 스크린샷만 준다. Instagram/X/Threads/YouTube 홍보를 요청한다. 결과: 확인된 기능만 사용, 수치 발명 금지, 4개 패키지의 다른 문체·형식, 이미지/영상은 제작 요청, 링크 미제공은 pending, 한국어 X 가중 길이 검사 상태, Shorts의 실행 가능한 CTA, 사용자 시간대 미지정 시 모든 패키지·일정이 Asia/Seoul.
2. 타인의 유튜브 URL을 줬지만 내용 접근이 실패한다. 결과: 못 본 내용을 분석했다고 말하지 않고 접근 가능한 자료로 진행; 타인 원본 대량 복제·성능 수치 인용을 피한다.
3. 기존 네이버 카페 글을 그대로 Reddit에 올리라고 한다. 결과: 정확한 subreddit 규칙 미확인은 표시, 영어·문맥·관계 공개를 반영한 초안 제공, 별도 게시 권한 없이 전송 금지.
4. 조회수가 상승했지만 가입은 0이다. 결과: 고객 확보 성공으로 판정하지 않음; 분모 0/누락 처리, 링크/착지/활성화 실험, 데이터 없는 CAC 발명 금지.
5. 사용자가 특정 계정과 검토된 버전의 게시를 이미 승인했다. 결과: 다시 승인 요청하지 않고 사용 가능한 도구로 실행; 실패 응답은 성공 처리 금지, 재시도 전 중복 확인.
6. Jev 판정 요청인데 모델/프로바이더가 불명확하다. 결과: 실제 가용성을 확인하고 unknown 또는 근거 기반 직접 검토; 가짜 endpoint 호출·boolean true로 자동 통과 금지.
