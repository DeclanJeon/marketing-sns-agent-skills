# 작업 시작
- 리소스: 문서/영상/이미지/URL/프로그램. 실제 읽을 수 있는 입력과 권리 상태.
- 홍보 대상: 원본 콘텐츠 조회, 제작자의 구독자 확보, 프로그램 활성 사용자, 상품 판매 중 무엇인가.
- 고객: 언어·지역·상황·기존 대안. 없으면 한 가지 임시 세그먼트.
- 목표: 목표 행동 한 개와 착지 URL. 없으면 제안하되 URL을 만들지 않기.
- 제약: 계정·현재 규모·작업 가능 시간·예산·브랜드 문체·금지 주제·보유 미디어.
- 범위: 전략/원고/제작/게시/광고. 실제 게시·전송은 사용자 지시와 연결 권한을 따로 확인.

필요한 질문 예: “목표를 콘텐츠 조회, 프로그램 체험, 구매 중 어디에 둘까요?”
원본 분석은 답변을 기다리는 동안 가능하다. 선택 채널이 이미 지정되면 다시 묻지 않는다.

## 최소/전체 모드
빠른 단일 채널 요청은 리소스 확인 → 채널 Worker → QA로 좁혀라. 전체 캠페인은 전체 DAG를 실행하라. 이미지/영상 제작을 요청받으면 해당 제작 스킬로 넘기고 게시 패키지에서 실제 파일 경로·상태를 기록하라. 이 패키지만으로 영상 렌더·API 게시 능력이 생기는 것은 아니다.

## 시간대 정규화
사용자 지정이 없으면 language=ko, timezone=Asia/Seoul로 초기화하라. 실행 환경의 UTC는 게시 시간대가 아니다. Worker 반환 시간대가 SSOT와 다르면 병합 전에 수정하라. 실제 착수일 미정은 D1 같은 상대일을 쓰되 시간대는 유지하라.
