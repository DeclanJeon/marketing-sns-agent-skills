# 채널별 제작→배포→개선

기본은 선택 채널별 완성 원고·명세를 만든다. 실제 제작 요청과 도구/권한이 있을 때만 렌더·이미지 생성·게시를 수행한다. 규격·기능·권리·광고 공개는 각 워커의 platform-checks와 현재 공식 문서/실계정으로 재확인한다. 이 표는 알고리즘 성공 공식이나 영구 규격표가 아니다.

## 제작 게이트
채널 worker는 content_id/revision마다 format, hook, body/script, scene/page specs, CTA route, accessibility, rights_needed, existing_assets, missing_assets, primary_kpi를 반환한다. 텍스트만 필요하면 미디어 생산 단계는 해당 없음으로 이유를 기록한다. 공통 마스터의 사실·장면은 재사용하되 크롭/길이/자막/음원/설명/링크 위치는 채널별 adaptation이다.

실제 제작은 운영 워커가 총괄에서 지정한 content-production-orchestrator/영상 제작·이미지 스킬에 task scope를 전달한다. 이들은 설치되어 있으면 읽고, 없으면 제작 명세+blocked를 반환한다. 완료 조건은 실제 파일·해시·재생/크기·자막·권리·원고 약속 회수다. 프롬프트/콘티만으로 produced를 표시하지 않는다.

## 배포 게이트
distribution은 순서(문제/과정→증거/시연→오퍼→질문 대응→후속 사례)를 목표에 맞게 구성하고 2주 local calendar를 만든다. 날짜·시간은 실제 사용자 일정과 데이터 기반 실험이며 최고의 시간이라고 보장하지 않는다. 각 게시물의 사용자 승인 범위·계정·final revision·CTA·자산·payload 검사에 연결하고 operations가 실제 실행을 맡는다. 콘텐츠별 duplicate key, 결과 조회, timeout unknown과 재검사 규칙을 유지한다.

실제 외부 게시가 요청되고 실행 가능하면 계속 진행한다. 도구/자산/규칙/권한 blocker는 그 게시물만 blocked로 남기고 다른 원고·수동 패키지를 완성한다. 일괄 게시 성공으로 요약하지 않고 각각 URL/ID·실제 시각·응답을 반환한다.

## 피드백
채널 metrics 정의·원자료→SNS measurement→사업 measurement에서 유입/활성화/거래·실입금/유지를 연결한다. 누락 귀속·dark social·중복·관측 기간·비용을 표시한다. 한 변수 변경 요청을 총괄에 반환하고 revision을 올려 영향 범위만 제작/검토/배포한다. 실제 관측 없으면 개선 가설만 제공한다.

## 제작 후 최종 QA
초기 DAG의 quality 단계는 원고 사전 검토다. 운영 워커가 제작을 인계하고 파일을 받으면 실제 asset hash와 payload revision을 총괄에 반환한다. 총괄은 영향받는 quality/semantic 검사를 새 검토 작업으로 수행하고 최종 preflight를 운영 워커에 넘긴다. 이것은 동일 DAG에 순환 의존성을 넣는 것이 아니라 새 자산 버전의 게이트/수정 작업이다. 자산이 미제작이면 최종 미디어 검사는 unknown이다. 비용·시간·규격을 바꾸는 제작 수정은 기존 승인 적용 범위를 확인하며 완료되지 않은 검사를 passed로 바꾸지 않는다.
