# 빠진 운영 과제를 처리하는 플레이북

## 목차
- 유료 광고·예산
- 검색 콘텐츠·SEO
- CRM·라이프사이클
- SNS 청취·댓글·이슈
- 채널 구조 재설계
- 실행 상태·중복 방지

이 절차는 B20의 통합 마케팅·디지털/직접 마케팅, B31의 콘텐츠·전환·후속 대응, B37의 채널 관리 주제를 바탕으로 만든 에이전트 운영 설계다. 책에 현재 플랫폼 API·알고리즘이 설명돼 있다고 주장하지 말라. 검색·광고·발송 시스템의 최신 정책과 기능은 실행 시 공식 자료로 확인하라. 지원하지 않는 연결이나 측정 데이터가 있으면 초안을 완성하고 해당 실행만 blocked로 기록하라.

## 유료 광고·예산
creative + social + measurement + pricing을 필요한 범위로 적용하라. 사업 목표·전환 이벤트·신규/기존 고객·광고 소재·랜딩·기간·총/일 예산·중단 조건을 정의하라. 예산은 추정 수익이 아닌 승인된 한도를 우선한다. 캠페인 표에 매체·대상·소재·전환 정의·예산·실제 지출·귀속 방식·오탐/중복 위험을 넣어라. 노출·클릭·귀속 매출·증분 이익을 구분하라. 집행 전 추적 이벤트·랜딩·가격·재고/용량을 확인하고 재배분도 승인 범위를 확인하라. 플랫폼 필수 항목·입찰·노출 규칙은 현재 API로 확인하라.

## 검색 콘텐츠·SEO
research + creative + measurement를 적용하라. 검색 의도·고객 질문·근거 있는 키워드 후보·기존 콘텐츠·경쟁 대안을 정리하라. 콘텐츠 브리프에 질문, 독자가 얻을 결과, 사실 출처, 구성, 제목, CTA, 내부 연결, 업데이트 담당을 포함하라. 완성 원고와 측정할 행동을 제공하라. 크롤링·색인·기술 수정이 필요하면 해당 웹 프로젝트와 권한이 있는 개발 도구로 인계하라. 순위·트래픽을 보장하거나 과거 책의 알고리즘 조언을 현재 규칙으로 강제하지 말라.

## CRM·라이프사이클
sales + success + cx + measurement를 적용하라. 동의된 고객 접점·리드 상태·담당·마지막 접촉·고객 결과·다음 행동을 정리하라. 온보딩/미구매/활성/위험/갱신별 트리거, 보내는 이유, 완성 메시지, 빈도 제한, 수신 거부, 중단 조건을 명시하라. 원치 않는 연락이나 중복 발송을 예방하고 계정·메시지·시점의 기존 권한 범위 안에서만 발송하라. 연락처·동의 정보·발송 성공·전환을 추정하지 말라.

## SNS 청취·댓글·이슈
social + cx + research를 적용하라. 자료의 수집 범위·시점·플랫폼을 기록하고 반응을 질문/불만/제안/가격 문의/위험 이슈로 나눠라. 대표 발언·빈도·표본 편향과 행동 가능한 시사점을 구분하라. 댓글 답변은 확인된 사실·해결 행동·연락 경로를 포함하라. 신원·주문 정보는 공개 댓글에 요청하지 말라. 확정되지 않은 문제는 조사 상태를 표시하고 원인·보상·해결 시각을 만들지 말라. 담당자·응답 약속·후속 확인 기준을 지정하라.

## 채널 구조 재설계
channel-retail + research + pricing을 적용하라. B37 첨부 L81의 세 가지 결정을 분리하라: 산업 채널 진단 → 기능/가치 사슬 재설계 → 파트너 정렬/영향. 현 구조와 최소 2개 대안에서 누가 탐색·판매·재고·배송·설치·지원·수금·데이터를 맡는지 비교하라. 고객 서비스 요구, 비용·마진, 권력·의존, 갈등, 전환 비용, 실행 책임과 시험 조건을 함께 제공하라. 매체별 역할표만으로 채널 재설계를 완료했다고 하지 말라.

## 실행 상태·중복 방지
assets/campaign-operations-template.json을 사용하라. 준비 단계는 preparation_status(draft/review/ready), 실제 실행 상태는 execution_status(not_started/blocked/executing/executed/failed/reconciliation_needed)로 분리하라. 연결·권한·검수가 부족하면 execution_status=blocked와 blocker 목록을 기록하되 준비 가능한 초안은 완성하라. ready는 실제 요청에서 승인된 범위와 가격·상품 조건·연결·필요 검수가 모두 확인됐을 때만 사용하라. 모델 판단을 게시 권한과 동일시하지 말라. 지연·오류가 나면 operation_key·게시물/발송 ID·결과 URL·실제 도구 상태로 먼저 조회하라. 성공 여부가 불명확하면 reconciliation_needed로 남기고 같은 내용을 자동 재게시·재발송하지 말라. 플랫폼이 제공하는 idempotency 기능이 있으면 사용하되 로컬 해시만으로 플랫폼 중복 방지가 보장된다고 하지 말라.
