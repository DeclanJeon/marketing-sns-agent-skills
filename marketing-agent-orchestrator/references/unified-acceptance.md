# 통합 수락 기준

- 구조: 통합 스킬 명단의 총괄은 하나, 나머지는 role=worker. 기존 SNS 총괄 이름은 별도 실행 루프를 만들지 않는다.
- 단일 업무: 가격 비교만 요청하면 channel worker를 실행하지 않으며 좁은 조합을 반환한다.
- 확장: 새 worker-capability를 발견하면 기존 recipe를 바꾸지 않고 extra_capabilities/새 channel family로 연결한다. 동일 기능 제공자는 명시 선택, 미등록/순환/충돌은 review다.
- 현금: 원가 기지급과 이익 원가를 구분하고 선지출/입금일/기한을 비교. 무료 SNS를 무료 주문 이행으로 착각하지 않는다.
- 채널: Instagram/Threads/X/YouTube 등 동일 핵심 약속이지만 완성 원고·CTA·형식은 채널별이다. URL/후기/영상 장면을 발명하지 않는다.
- 제작: 기획 명세와 실제 파일을 분리. 렌더 파일 없음은 blocked/requested이며 generated/published 아님.
- 배포: 실제 게시 요청과 연결이 있으면 승인 범위 내 실행. 도구 부재/timeout/권리 미확인은 정확한 상태와 재개 조건을 반환한다.
- 판정: Jev/호환 공급자 명시 선택, 미설정/미교정은 review. 구조 테스트와 model accuracy를 혼동하지 않는다.
- 예산: 공수 미확인은 unknown. 요청 채널을 몰래 버리지 않고 최소안/균형안/확장안 비교와 일정 분산을 제공한다.
- 근거: 기존 책 장별/152개 원칙 검증 미완료 상태는 유지하며 통합 코드 QA로 완료 처리하지 않는다.
