# 의미·실계정 검사

검토 대상은 content_id/revision과 정확한 문구·자산이다. 각 검사에 pass/fail/unknown, evidence, 이유와 수정안을 남겨라. 의미 검토는 구조 검사와 별개이며 검토자 모델을 실행하지 않았다면 실행했다고 쓰지 말라.

- 의미: 원고의 주장별 claim_id/locator를 대조하라. 원본의 조건·부정·불확실성이 축약 중 사라졌는지, 영상이 실제 제품 시연처럼 보이는 합성인지 확인하라. 고객 약속과 훅이 본문에서 충족되는지 보라.
- 채널 적합성: 첫 화면의 요점, 모바일 가독성, 대화 문체/직업적 문체, 영상에서 실제 말할 수 있는 분량, 채널별 새로운 가치를 확인하라. 단순한 동일 문구 복제는 수정하라.
- 접근성: 미디어 재생, 자막 싱크·오타, 텍스트 대비·가독성, 안전 영역·잘림, alt text를 검사하라. 파일을 보지 못하면 unknown이다.
- 기능: 해당 계정/surface의 실제 게시 화면 또는 공식 근거로 규격·길이·CTA 동작을 확인하라. 브라우저/연결 도구 권한이 없으면 수동 체크리스트로 넘겨라. 실제 게시 버튼은 검증 요청만으로 누르지 말라.
- 클릭 CTA: 게시 위치→링크→착지 화면→폼/체험/구매 행동. 실제 요청한 행동이 가능한지 확인하라. 제출·구매·타인에게 보내기는 기존 요청 범위를 따른다.
- 권리: 자료 소유/사용권, 음원·얼굴·브랜드 및 필요한 공개 사항의 실제 근거를 기록하라. 검사 항목 자체가 사용 허가를 만들지 않는다.

ready 전에 모든 필수 항목을 해결하라. 게시 payload 해시와 자산 해시에 묶인 운영 preflight로 반환하라. 원고 변경, 재렌더링, 계정/CTA 변경 후 이전 pass를 자동 승계하지 말라. 메트릭을 검토할 때는 관측 데이터와 주장/실험을 분리하라.
